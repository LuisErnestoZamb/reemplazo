# AGENTS.md

## What this is

- From-scratch OS written in **Rust** for a 2007 MacBook2,1 (hardware below). You are establishing structure, build, and test conventions; document them here as they land.
- Required deliverables, all in Rust in this workspace: kernel + low-level OS services, a command line (shell with **minimal builtins only** — not BusyBox/GNU/FreeBSD parity; grow on demand), an **opencode-like AI client with a VSCode-like editor**, a browser, **git** (clone/commit/fetch/push vs GitHub over ssh or https), **ssh client + server**, and an **installer**: bootable ISO **plus a network installer** (fetch the system over the network with the OS's own stack — sky2, DHCP, DNS, TCP/TLS).
- Dev happens on the **modern Mac (this checkout)**; the 2007 MacBook is the *target*, cross-compiled for. (opencode itself cannot run on the target — that's the point of the project.)

## Target hardware — hard constraints

- **CPU:** Core2 Duo T7400 (Merom, family 6 model 15), 2C/2T @ 2.16 GHz, x86-64 + VT-x, 4 MB L2.
- **ISA ceiling: SSSE3.** No SSE4.1, no SSE4.2, no POPCNT, no AVX → baseline is **x86-64-v1**. This is the single most important constraint in the repo.
- **RAM:** 2.9 GB DDR2-667 (2 slots, 4 GB max).
- **Disk:** 120 GB SATA 5400 rpm — the bottleneck. Budget runtime I/O accordingly.
- **Boot:** 32-bit Apple EFI running BIOS emulation → **GPT + `bios_grub` + GRUB i386-pc**. No macOS on disk; current Debian 13 install (~450 MB idle, IceWM + lightDM) is what this OS replaces.
- **Peripherals** (verified working under Debian — use these as hardware IDs when writing drivers):
  - GPU: Intel GMA950 (Xorg `intel`), 13.3" 1280x800
  - NIC: Marvell 88E8053 GbE (`sky2`) — wired + DHCP is the reliable dev path
  - WiFi: Atheros AR5418 a/bgn (`ath9k`) — radio OK, no credentials configured yet
  - Audio: HDA (`PipeWire` on Debian) · SMC/fan: `applesmc` + `coretemp`
  - DVD SuperDrive boots ISOs via **Option/C** — the primary way to test on real hardware
  - Bluetooth: present, disabled
- Network dev split (from the QEMU smoke scan): QEMU's NIC is **e1000** (`8086:100e`) — develop the TCP/IP stack against it; the MacBook's **sky2** (Marvell 88E8053, `11ab:4362`, constant `pci::SKY2_88E8053`) is *not* in QEMU, so the sky2 driver can only be validated on real hardware.

## Mistakes to avoid

- **Never build with `-C target-cpu=native`** or any host-feature detection: the build host is a modern Mac, the target is a T7400. Native code will emit SSE4+/AVX and die with SIGILL on the target. Pin the baseline explicitly (x86-64-v1 / no SSE4+ flags) and prefer `x86_64-unknown-none` (rustup-installable, `no_std`) over ad-hoc targets.
- **Don't plan an x86_64 UEFI bootloader or ESP.** Firmware is 32-bit EFI in BIOS-emulation mode; the boot chain is GRUB i386-pc → kernel. `x86_64-unknown-uefi` is the wrong path.
- **Don't assume headroom.** 2.9 GB RAM and a 5400 rpm disk rule out heavyweight runtimes, large indexes, and chatty logging at rest.
- **Networking is on the early critical path** (not "later"): clone/push vs GitHub, sshd, and the network installer all need sky2 → DHCP → DNS → TCP/IP → TLS 1.2+ / ssh (GitHub rejects legacy sha1 ssh-rsa). Prioritize the network stack accordingly.

## Workflow

- Git: branch `main`, remote `git@github.com:LuisErnestoZamb/reemplazo.git`. Commits: conventional (`feat:`, `fix:`, `docs:`, `build:`), one milestone per commit, message records what was actually verified.
- **Before every commit:** `cargo xtask check` (fmt + clippy for host crates *and* kernel target + host tests + kernel cross-build). Kernel is never linted/tested for the host — it is `x86_64-unknown-none` only.
- **Boot smoke test:** `cargo xtask smoke` — builds the ISO, boots it headless, asserts each milestone's serial marker in order (`BOOT_OK → VGA_OK → MEM_OK → ALLOC_OK → RTC_OK → PCI_OK → USB_KBD_OK → E1000_OK → NET_OK → PING_OK → DHCP_OK → DNS_OK → TCP_OK → TLS_OK → HTTP_OK → GIT_LSREMOTE_OK → GIT_FETCH_OK → SSH_KEXINIT_OK → INT_OK → TUI_OK → EDITOR_OK → AI_CHAT_OK → BROWSER_FETCH_OK → AI_EDIT_OK → SHELL_OK → KEYBOARD_OK`) within 30s (boot phase) + 15s (keyboard phase). This is the test that catches broken boot (header/trampoline/paging/mbi), the VGA text mirror, frame-allocator, kernel heap (contiguous carve + global allocator + `Vec` proof), CMOS RTC, PCI-scan, UHCI enumeration + HID boot-keyboard descriptor/report parsing and set-1 translation (`usbwire`, `kernel/src/usb.rs`), e1000-driver, network-path, DHCP/DNS/TCP-client, TLS/HTTP-client, git ls-remote (smart-HTTP advertisement), git fetch (v0 upload-pack want/`deepen 1`/done POST → raw pack → `git-pack` header/zlib/delta/trailer decode + in-memory index → iterative commit→tree→blob walk with depth/entry/path caps), ssh-kexnegotiation (banner + `SSH_MSG_KEXINIT` algorithm intersection), interrupt (IDT/PIC/PIT), the screen layer (off-screen cell diff flush into the text buffer, ratatui `Backend`, full-frame readback from `0xb8000`), the editor (gap buffer + line index edits with undo/redo, viewport frame with gutter/status read back from `0xb8000`), the AI chat client (OpenAI-style request built and serde_json reply parsed over `net::http` POST against the in-container mock, chat-pane read back from `0xb8000`), the editor↔AI integration (A5: the retained document quoted into a mock exchange, the completion applied at the editor cursor with an undo/redo round-trip asserted on the buffer, the resulting editor frame read back from `0xb8000`), the browser fetch (URL parse/resolve through `url` + redirect-following HTTP(S) GET against `github.com` — plain `301` hop resolved through `Url::join`, TLS hop, bounded body counted), serial-shell, or keyboard (i8042 bring-up → set-1 decode → line discipline → builtin; with the smoke's `usb-kbd` attached QEMU routes `sendkey` through the UHCI/HID wire into that same set-1 decoder) code. `KEYBOARD_OK` is typed into the guest by xtask over QEMU's HMP monitor (`sendkey`, TCP port derived from the checkout path — see `qemu_std_args`); the marker must be the shell's `echo` output, not the input echo. QEMU runs with user-mode networking (`slirp`: guest 10.0.2.15, gateway 10.0.2.2, DNS 10.0.2.3 — constants in the `net` crate, asserted by the DHCP client). `DNS_OK`, `TCP_OK`, `TLS_OK`, `GIT_LSREMOTE_OK`, `GIT_FETCH_OK`, `SSH_KEXINIT_OK` and `BROWSER_FETCH_OK` need working outbound network through Docker's resolver (they resolve and fetch `github.com`, and `github.com:22`), so the smoke test needs network access; `AI_CHAT_OK` and `AI_EDIT_OK` need **no internet** — they post to the chat mock xtask runs beside QEMU (slirp sends guest→10.0.2.2:8099 to the container's loopback).
- **Installer smoke test:** `cargo xtask smoke-install` — same ISO plus a 64 MiB `target/iso-root/disk.img` that is a **valid FAT16 volume** (magic pattern at LBA0 in the boot sector's boot-code area, offset 62 — see `kernel/src/ata.rs`; the BPB at 11..62 and the `55 AA` at 510 stay spec-shaped) attached with `-drive file=/iso/disk.img,if=ide,format=raw`, asserting `BLK_OK` … `FAT_OK` … `FS_WRITE_OK` … `GIT_CHECKOUT_OK` (the ATA PIO probe of the legacy primary channel, then the FAT mount + byte-exact `/README.TXT` read in `kernel/src/fs/` over the `fat` crate, then the **write path**: the kernel writes `/RESULT.TXT`, re-mounts from scratch — a fresh `fat::Fat16` over a fresh block handle — and reads it back byte-exact while re-checking `/README.TXT` for clobbering; then, in the network phase, G3's fetch checks the fetched repo's 8.3-representable **root-level** blobs out through `fs::checkout_root`, re-mounts and asserts `/README.md` byte-exact and containing `AGPL` — the `fat` crate has no `mkdir`/LFN writer yet, so nested and long-named files are counted as skipped, not silently mangled) within 30s. The main `smoke` runs with **no disk** — `ata::probe` prints nothing when no drive answers and `fs::prove` is never reached, so its marker chain is untouched. The driver is PIO/LBA28 reads *and writes* (no ATAPI/IRQ/DMA) with every poll bounded, so it can never hang boot; `fat`'s writes are write-through (FAT → data → directory entry, no crash consistency yet — see `fat::write`).
- Interactive boot: `cargo xtask run` (Ctrl-C quits; stale VM containers are force-cleaned on next run) drops into the serial shell — type `help`. Local terminals line-buffer, so for live echo run `stty raw -echo` in the terminal first. `run` also prints QEMU's monitor address (`127.0.0.1:<port>`) — inject keystrokes with `printf 'sendkey h\nret\n' | nc 127.0.0.1 <port>` (the QEMU `sendkey` path; the MacBook's real keyboard needs the UHCI/HID milestone).
- Single test: `cargo test -p mbi <name>`.
- **Progress reporting:** after every commit or completed milestone, the summary must include a "what remains" table (deliverable → milestone state → what's left), so the distance to "todo terminado" is visible at each step.
- Toolchain quirk (macOS 13, verified): no native `grub-mkrescue`, and Homebrew **cannot** build QEMU (Tier 3 → source build fails). Everything runs in the `reemplazo-tools` image (`tools/Dockerfile`: grub + xorriso + qemu); xtask prefers a host `qemu-system-x86_64` if one ever exists. Docker daemon must be running.
- `kernel` never builds with bare `cargo build` (excluded via `default-members`); it is built via `cargo xtask build` with `--target x86_64-unknown-none`.
- Verify against QEMU first; validate on real hardware via Option/C DVD or USB boot.
